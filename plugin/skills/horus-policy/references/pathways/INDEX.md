# Pathway packs index

The six advisory pathways the Principal selects from after intake, with the enum value used in `engagement.pathway`, the appraisal kind, the core Tier-2 deliverables and the anchor frameworks. Each pack follows the fixed format in CONVENTIONS.md so a new pathway is one new file plus benchmark entries.

When Horus uses this: at P0 to find the candidate packs after running `classification.md`, and at every phase to open the primary pack (and any secondary pack) for the section that governs the current work.

## How the packs are used

- **Classification first.** `classification.md` holds the twelve questions, the `problem_classification` record shape, the hybrid rules and the AP2 revisit procedure. The pack is opened only after the primary and secondary pathways are recorded in `engagement.pathway`.
- **One section per phase.** P1 reads Classification signals (to confirm) and Frameworks (to populate `approach.frameworks[]`). P2 reads Diagnostic lens and Stakeholder emphasis. P3 reads Option logic. P4 reads Appraisal method, which names the appraisal `kind`, the `standards_applied` strings, the toolkit modules and the required method-specific block. P5 reads Core Tier-2 deliverables and structures. Every gate reads Gate criteria variants, which extend the common checklists in STATE_SCHEMA.md section 7.
- **Hybrids.** The primary pack governs the engagement; a secondary pack contributes option kinds, appraisal kinds and deliverables for the component it covers, as set out in `classification.md`. `appraisals.pathway` records which pack defined each appraisal's method.
- **Benchmarks.** Each pack's Benchmark documents section cites BENCHMARKS.md entries by reference (B1, C2 and so on). The catalogue is strongest on the regulatory pathway and on decision memos; the other packs list the gaps the build must close before they are finalised.
- **Proposed schema additions.** Where a pack needs a record, deliverable type or content shape that STATE_SCHEMA.md does not yet define, it says so in a closing note rather than inventing one. Current proposals: `legal_change_inventory`, `routines_design`, `capability_plan` and `cost_to_serve_summary` deliverable types; content shapes for `institutional_diagnostic`, `delivery_chain` and `user_and_service_research`; structured `engagement.pathway.secondary[]`.
- **Adding a pathway.** Write one new file in this folder with the ten required sections, add its benchmark entries to BENCHMARKS.md, add the enum value to STATE_SCHEMA.md and the appraisal kind and method block if the method is new, and add a row to this table.
